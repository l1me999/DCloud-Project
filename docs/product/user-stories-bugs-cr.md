## User Stories

### US-01 · Загрузка с шифрованием

**Приоритет:** Must · **Спринт:** S1 · **SP:** 5 · **Статус:** Done

Как сотрудник, я хочу загрузить файл и увидеть, что он зашифрован до сохранения, чтобы данные не уходили в открытом виде.

**Критерии приёмки:**

- файл до 20 МБ загружается: 201, карточка в списке, SHA-256;
- в каталогах узлов только шифротекст, ключа нет;
- больше 20 МБ или неподдерживаемый тип: 400/413, частичных файлов нет;
- ошибка шифрования: 500, метаданные не создаются.

### US-02 · Прогресс загрузки

**Приоритет:** Could · **Спринт:** S2 · **SP:** 2 · **Статус:** Backlog

Как сотрудник, я хочу видеть прогресс загрузки, чтобы понимать, что процесс идёт.

**Критерии приёмки:**

- прогресс 0–100% и текущее состояние;
- обновление не реже раза в 250 мс или на каждый фрагмент;
- успех: 100%, сообщение, список обновлён;
- ошибка: прогресс остановлен, показана ошибка.

### US-03 · Отмена загрузки

**Приоритет:** Could · **Спринт:** S2 · **SP:** 2 · **Статус:** Backlog

Как сотрудник, я хочу отменить загрузку, чтобы не ждать ошибку.

**Критерии приёмки:**

- отмена прерывает запрос, файла в списке нет;
- частичные фрагменты и метаданные удаляются или помечаются aborted;
- после завершения кнопка отмены недоступна;
- при ошибке сети интерфейс сбрасывается.

### US-04 · Валидация файла

**Приоритет:** Should · **Спринт:** S1 · **SP:** 2 · **Статус:** Done

Как сотрудник, я хочу получить понятную ошибку при неподдерживаемом размере или типе файла, чтобы быстро исправить выбор.

**Критерии приёмки:**

- файл больше 20 МБ: ошибка, кнопка загрузки disabled;
- неподдерживаемый тип: ошибка со списком типов, disabled;
- корректный файл: ошибка очищена, кнопка активна;
- серверная проверка: 400/413 с кодом, сообщение в UI.

### US-05 · Ключ не на узлах

**Приоритет:** Must · **Спринт:** S1 · **SP:** 3 · **Статус:** Done

Как CISO, я хочу видеть, что ключ не хранится на узлах, чтобы доверять E2EE.

**Критерии приёмки:**

- в каталогах узлов нет DEK, мастер-ключа и открытого текста;
- API не возвращает ключ;
- расшифровка ключом из защищённого хранилища метаданных;
- ключ отсутствует или повреждён: 409/500, без выдачи шифротекста.

### US-06 · Карта фрагментов

**Приоритет:** Must · **Спринт:** S2 · **SP:** 3 · **Статус:** Done

Как CISO, я хочу видеть, на какие узлы разложены фрагменты, чтобы контролировать размещение данных.

**Критерии приёмки:**

- карта: индекс, размер, SHA-256, узлы, статус реплик;
- 3 реплики на разных узлах;
- offline узел: реплики помечены, показан остаток;
- нет фрагментов: пустое состояние.

### US-07 · Статус узлов

**Приоритет:** Should · **Спринт:** S2 · **SP:** 2 · **Статус:** Done

Как CISO, я хочу видеть статус узлов онлайн/офлайн, чтобы понимать доступность хранилища.

**Критерии приёмки:**

- 5 узлов: статус, занято/доступно, последняя активность;
- offline: статус обновляется до 2 с, реплики помечены;
- все онлайн: зелёный статус;
- ошибка API: сообщение и кнопка повторить.

### US-08 · Имитация отказа узла

**Приоритет:** Should · **Спринт:** S2 · **SP:** 3 · **Статус:** Done

Как CISO, я хочу имитировать отказ узла, чтобы проверить отказоустойчивость.

**Критерии приёмки:**

- «Отключить»: узел offline, новые фрагменты не получает;
- offline + другие реплики: скачивание успешно;
- «Включить»: узел онлайн, принимает реплики;
- все offline: 409 при загрузке/скачивании.

### US-09 · Реплики на разных узлах

**Приоритет:** Should · **Спринт:** S2 · **SP:** 3 · **Статус:** Done

Как CISO, я хочу видеть, что реплики не лежат на одном узле, чтобы снизить риск потери данных.

**Критерии приёмки:**

- у каждого фрагмента 3 реплики на разных узлах;
- нет двух реплик на одном узле;
- отказ узла: минимум 2 доступные реплики, файл скачивается;
- меньше 3 узлов: 409 при загрузке.

### US-10 · Скачивание файла

**Приоритет:** Must · **Спринт:** S1 · **SP:** 3 · **Статус:** Done

Как сотрудник, я хочу скачать файл и получить исходное содержимое, чтобы пользоваться хранилищем.

**Критерии приёмки:**

- исходные байты, правильное имя и content-type;
- сборка по порядку и расшифровка;
- missing/corrupt chunk: 409/500, без частичного файла;
- нет файла: 404.

### US-11 · Проверка целостности

**Приоритет:** Must · **Спринт:** S1 · **SP:** 2 · **Статус:** Done

Как сотрудник, я хочу видеть проверку целостности после скачивания, чтобы быть уверенным, что файл не повреждён.

**Критерии приёмки:**

- SHA-256 совпадает: «Целостность подтверждена»;
- не совпадает: 409, файл не отдаётся;
- хеш фрагмента не совпадает: реплика отклоняется, берётся другая;
- все реплики повреждены: ошибка с индексом фрагмента.

### US-12 · Восстановление после отказа

**Приоритет:** Must · **Спринт:** S2 · **SP:** 5 · **Статус:** Done

Как CISO, я хочу восстановить файл при отказе одного узла, чтобы не терять доступ к данным.

**Критерии приёмки:**

- 1 узел offline: скачивание с оставшихся реплик;
- 2 узла offline: успех, если есть по реплике;
- все реплики фрагмента offline: 409 с индексом;
- узел снова online: карта обновлена, скачивание успешно.

### US-13 · Ошибка при нехватке реплик

**Приоритет:** Should · **Спринт:** S2 · **SP:** 2 · **Статус:** Backlog

Как CISO, я хочу получить ошибку, если доступных реплик недостаточно, чтобы понимать границы отказоустойчивости.

**Критерии приёмки:**

- меньше 3 узлов: 409 «недостаточно узлов для 3 реплик»;
- меньше 1 реплики: 409 с индексом и количеством;
- UI: понятное действие (включить узел/повторить);
- после восстановления узлов операция успешна.

### US-14 · Список файлов

**Приоритет:** Must · **Спринт:** S1 · **SP:** 3 · **Статус:** Done

Как сотрудник, я хочу видеть список файлов с метаданными, чтобы быстро находить нужный файл.

**Критерии приёмки:**

- список: имя, размер, дата, статус, число фрагментов;
- пусто: состояние US-17;
- после загрузки/скачивания/удаления список обновляется;
- ошибка API: сообщение и «Повторить».

### US-15 · Удаление файла

**Приоритет:** Should · **Спринт:** S2 · **SP:** 2 · **Статус:** Backlog

Как сотрудник, я хочу удалить файл и все его фрагменты, чтобы освобождать место и убирать данные.

**Критерии приёмки:**

- подтверждение: 204, метаданные и реплики удалены;
- отмена: ничего не удалено;
- нет файла: 404;
- список обновлён, место освобождено.

**Критерии приёмки:**

## Баги

### BUG-01 · Падение скачивания при повреждённой реплике

**Приоритет:** Must · **SP:** 2 · **Статус:** Done

BUG-01. При повреждении одной реплики скачивание падает с 500.

Серьёзность: критический

Приоритет: Must

Оценка: 2 SP

Обнаружен: на приёмочном тестировании / Hardening после Sprint 2

Затрагивает: US-11 «Проверка целостности», US-12 «Восстановление после отказа»

Шаги воспроизведения:

1. Загрузить файл больше 16 КБ, чтобы получилось несколько фрагментов.
2. Повредить файл одной реплики на node-1.
3. Нажать «Скачать».

Ожидаемо:

- сервис обнаруживает несовпадение SHA-256;
- пробует следующую реплику;
- отдаёт файл, проверка целостности проходит.

Фактически:

- скачивание завершается ошибкой 500;
- файл не отдаётся, хотя реплики на node-2 и node-3 доступны.

Причина:

- в цикле сборки не обрабатывается ошибка чтения/проверки одной реплики;
- нет fallback на следующую реплику.

Исправление:

- обрабатывать ошибку каждой реплики;
- проверять SHA-256 фрагмента;
- переходить к следующей реплике;
- возвращать 409 только если все реплики недоступны;
- добавить регрессионный тест.

Проверка:

- одна повреждённая реплика → скачивание успешно;
- все реплики повреждены → 409 с индексом фрагмента;
- тест выполняется в CI.

Статус: исправлен hotfix-ом после Sprint 2; velocity Sprint 2 — 20 SP, состав спринта не менялся.

## Change Requests

### CR-01 · Экспорт карты фрагментов в CSV

**Приоритет:** Must · **SP:** 2 · **Статус:** Backlog

> На карточке стоит метка «Must»; в описании указан приоритет «Should».

Change Request CR-01 от CISO: экспорт карты фрагментов в CSV для внутреннего аудита 152-ФЗ.

Спринт: S2

SP: 2

Приоритет: Should

Владелец: Dev

Срок: до Sprint 2 Review

Зачем: CISO должен прикладывать карту фрагментов к аудиту хранения и подтверждать размещение реплик по узлам.

AC:

- кнопка «Экспорт CSV» в окне «Карта фрагментов»;
- CSV: имя файла, индекс фрагмента, размер, SHA-256, node_id, статус реплики, дата экспорта;
- UTF-8, разделитель «;»;
- без ключей и секретов;
- работает для файла с одним и несколькими фрагментами;
- нет файла — 404; нет фрагментов — CSV с заголовком;
- экранировать значения, начинающиеся с =, +, -, @;
- тест на экспорт.

Решение: CR-01 принят, заменяет US-13 (2 SP). US-13 возвращена в бэклог. Sprint 2 остаётся 20 SP, Sprint Goal не меняется.

Зависимость: US-06 «Карта фрагментов».
